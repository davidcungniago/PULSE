# P6/P7 — integrasi API dan MVP Pulse

## P6: vertical slice aset

Alur: `AssetListScreen` / `AddAssetForm` → notifier Riverpod → `AssetRepository` → `AssetService` → Dio → FastAPI → SQLAlchemy → SQLite/PostgreSQL. `POST /api/projects/{id}/assets` menyimpan aset; `GET` pada URL yang sama memuat kembali data. Model menggunakan JSON PascalCase. Membuka layar tidak memicu pemindaian.

Daftar memiliki loading, kosong, error dengan retry, serta data. Form menampilkan validasi inline, menonaktifkan submit saat mengirim, mempertahankan input saat gagal, dan menutup dengan pesan sukses setelah tersimpan. Notifier menolak submit ganda. Respons JSON rusak tidak diperlakukan sebagai daftar kosong.

Unit test P6 terdapat di `test/services/asset_api_test.dart`: model valid, model invalid, API sukses (termasuk metode/path/body POST), data kosong, HTTP gagal, JSON rusak, dan respons null. Adapter HTTP palsu memastikan tidak ada jaringan dalam unit test. Test widget enam kondisi ada di `test/features/asset_management/asset_list_screen_test.dart`.

## P7: alur demo

1. Daftar akun, lalu masuk. Coba email duplikat atau kata sandi salah untuk melihat error.
2. Buat proyek. Data proyek tersimpan di backend. Ubah nama/deskripsi lewat "Ubah proyek". Penghapusan memerlukan konfirmasi dan hanya diizinkan untuk proyek tanpa aset supaya riwayat tidak hilang.
3. Tambah URL repository, baik diketik maupun dari kamera QR. Coba URL salah/duplikat. Batal kamera kembali ke form tanpa menghapus input.
4. Buka aset dan tekan "Pindai Sekarang". Hasil komponen/CVE berasal dari backend. Repository privat, GitLab yang belum didukung untuk scan, manifest tidak tersedia, atau OSV gagal menghasilkan error yang dapat dicoba ulang.
5. Buka dashboard. Statistik dihitung dari scan terbaru. "Pindai Semua Aset" berjalan berurutan dan melaporkan kegagalan per aset tanpa menghentikan aset lainnya.
6. Ubah versi dependensi pada repository uji yang Anda kelola, lalu pindai kembali. Drift ditampilkan, sedangkan hasil scan terdahulu tetap tersimpan. Pemindaian pertama tidak menghasilkan drift.
7. Buka riwayat peringatan. CVE kritis baru atau drift membuat alert email. SMTP tidak dikonfigurasi/gagal ditampilkan sebagai "Email gagal terkirim"; hasil scan tetap tersimpan.
8. Ubah aset untuk mengaktifkan/menonaktifkannya. Aset nonaktif tidak masuk pemindaian semua. URL aset yang telah memiliki riwayat tidak boleh diganti; buat aset baru agar identitas riwayat tetap benar.
9. Keluar, lalu masuk dengan akun kedua: proyek akun pertama tidak dapat diakses. Sesi invalid/kedaluwarsa mengarahkan ke login saat API mengembalikan 401.

## Tiga advanced feature

| Fitur | Manfaat | Implementasi dan batasan |
|---|---|---|
| Autentikasi | Memisahkan proyek antar pengguna | Password bcrypt, JWT HS256 bertenggat, otorisasi pemilik di backend, token disimpan melalui secure storage. Gunakan HTTPS di produksi. |
| Notifikasi email | Pengguna dapat menerima temuan tanpa membuka aplikasi | SMTP terinjeksi dan riwayat status pengiriman. Memerlukan konfigurasi SMTP; tidak menggunakan push/local notification perangkat. Test menginjeksi pengirim palsu. |
| Kamera QR | Mempercepat pengisian URL dan mengurangi salah ketik | Kamera hanya dibuka atas aksi pengguna. QR harus berisi URL GitHub/GitLab yang valid. Penolakan izin/kamera tidak tersedia ditampilkan dengan retry, batal, dan alternatif input manual. |

Notifikasi email tidak meminta izin notifikasi perangkat. Kamera memerlukan izin Android/iOS/browser. Web membutuhkan localhost atau HTTPS. Verifikasi kamera fisik dan email ke kotak masuk nyata membutuhkan perangkat serta konfigurasi pengguna; test otomatis tidak membuktikan kedua hal tersebut.

## Menjalankan

Backend (PowerShell, dari `backend/`):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:JWT_SECRET = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Simpan JWT_SECRET yang stabil di environment deployment untuk mempertahankan validitas sesi setelah restart. Contoh di atas membuat kunci baru setiap dijalankan. `backend/.env.example` mencantumkan variabel yang diperlukan; jangan commit `.env`. Seed opsional membutuhkan `DEMO_PASSWORD` dari environment; pengguna dapat langsung register tanpa seed. `DATABASE_URL` default SQLite; URI PostgreSQL tetap dapat digunakan dengan migrasi yang sama.

Flutter (root):

```powershell
flutter pub get
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8000
```

Android emulator menggunakan `--dart-define=API_BASE_URL=http://10.0.2.2:8000`. HTTP lokal diizinkan hanya untuk build debug Android; produksi menggunakan HTTPS. Daftar pantau lokal yang telah ada tetap memakai penyimpanan lokal.

## Pemeriksaan

```powershell
dart format lib test
flutter analyze
flutter test --reporter expanded
flutter build web --no-wasm-dry-run
```

Dari `backend/`:

```powershell
.\.venv\Scripts\python.exe -m ruff format app tests scripts alembic
.\.venv\Scripts\python.exe -m ruff check app tests scripts
.\.venv\Scripts\python.exe -m pytest -q
```

Unit/API test menggunakan SQLite in-memory dan fake GitHub/OSV/SMTP, tidak mengakses jaringan. `scripts/smoke_api.py` adalah pemeriksaan manual HTTP lokal terpisah: jalankan API pada port 8765 dengan database demo terpisah, lalu `python -m scripts.smoke_api` memakai `DATABASE_URL` yang sama. Script membuat akun/proyek/aset demo, memuat kembali lewat HTTP, dan memeriksa persistensi dari sesi database baru; tidak mencetak token/password.

Keterbatasan pemindai tetap mengikuti arsitektur: manifest GitHub publik, versi baseline/pinned, tanpa resolusi dependency transitif atau Syft; lisensi yang tidak tersedia ditampilkan "Tidak diketahui". Kontrol "Mode Demo (Debug)" hanya untuk screenshot kondisi UI, bukan bukti koneksi API.

Belum diverifikasi pada perangkat Android/iOS, kamera fisik, PostgreSQL aktif, atau kotak masuk email nyata. SMTP sengaja tidak diaktifkan pada demo lokal. Pengiriman notifikasi, kegagalan SMTP, isolasi akun, JWT kedaluwarsa, dan preservasi riwayat diverifikasi dengan test terisolasi; ini bukan pengganti uji perangkat dan SMTP sebelum penyerahan.
